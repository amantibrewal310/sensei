# sensei — Design

**Date:** 2026-07-01
**Status:** Approved for planning
**Goal:** A from-scratch, single-app rebuild of the core "teach by speaking + drawing live" experience.
Clarity beats fidelity — keep the two novel ideas, drop everything incidental.

---

## 1. Purpose & Philosophy

A single Next.js app: a user types a topic, and a teacher agent **speaks and draws on a canvas in
real time, step by step**, while the user can interrupt by voice or text.

**Keep (the magic):**
- **NDJSON streaming** — the teacher LLM emits one JSON action per line, parsed incrementally so
  speech and drawing begin before the full response arrives.
- **SVG-diff animation** — the teacher describes *what to draw* in plain English; a second LLM
  translates that into line-level SVG edits (`start_line`, `end_line`, `content`) applied one-by-one
  with a small delay, so the drawing animates.

**Drop (incidental complexity):** LiveKit rooms + data-channel protocol, the separate Python agent,
the Express backend, Postgres and all roadmap/node/snapshot tables, auth/anonymous IDs,
projects/lessons, resume, S3 uploads, non-English TTS, the pause controller with inactivity timeout,
follow-up node insertion + roadmap regeneration.

---

## 2. Architecture — one Next.js app

No separate agent service, no backend service, no database. Session state lives in the browser
(React). The server is a set of **stateless route handlers**, pure functions of their input.

```
Browser (React) ── holds session state, drives the teaching loop
  ├─ POST /api/plan           → Claude returns 3–4 teaching steps (once per session)
  ├─ POST /api/teach   (SSE)  → Claude streams NDJSON actions for ONE turn
  ├─ POST /api/draw-svg (SSE) → Claude streams line-level SVG edits
  └─ GET  /api/realtime-token → mints an ephemeral OpenAI Realtime key
Canvas (SVG)  ◄── incremental edits applied with an animation delay
Voice layer   ◄── OpenAI Realtime (mic capture + playback + VAD + barge-in + input transcription)
```

**The client orchestrates the teaching loop.** Server routes hold no session state.

### Tech
- Next.js 16, React 19, TypeScript, Tailwind.
- Claude via the official `@anthropic-ai/sdk` for all reasoning (teacher + SVG agent).
- OpenAI Realtime API for the voice layer.

## 3. The Teaching Loop (the heart)

The original prototype used `planning / continue_explain / node_done / complete / engage` plus
pre-speak / post-speak plus an auto-turn gating state machine. We collapse this to **four actions**:

```json
{"type":"plan","intent":"teach"}
{"type":"speak","text":"Why does JavaScript even need an event loop..."}
{"type":"draw","instruction":"Draw a single-threaded call stack with a queue beside it"}
{"type":"done"}
```

Flow for one turn:
1. Client calls `POST /api/teach` with `{ steps, currentIndex, transcript }`.
2. Claude **streams NDJSON**; the client parses it line-by-line as it arrives.
3. `speak` text → handed to the voice layer to be spoken.
4. `draw` instruction → `POST /api/draw-svg`. Speech and drawing run in parallel.
5. On `done`, once both speech and drawing have finished, the client auto-advances to the next step.
6. A user voice/text interruption pauses the loop and starts a new `/api/teach` turn that includes
   the user's input in `transcript`.

Turn shape is validated against a small schema; malformed lines are skipped, not fatal.

---

## 4. The Drawing Loop (SVG diff)

1. Client sends the current SVG (pretty-printed, **line-numbered**) + a PNG snapshot of the canvas
   + the plain-English draw instruction + canvas width.
2. Claude (`claude-opus-4-8`) streams edits as partial JSON; the route parses complete edits
   incrementally and emits them over SSE:
   `{ "start_line": N, "end_line": M, "content": "<svg fragment>" }`.
3. The client applies each edit to the working SVG via `applySvgLineEdit`, re-rendering the canvas
   after each, with a ~0.5s delay between edits so the drawing animates.
4. When the stream ends, the final SVG becomes the new canvas state.

The SVG agent's system prompt (drawing rules, coordinate constraints) is **prompt-cached**.

## 5. Models

| Role | Model | Notes |
|------|-------|-------|
| Teacher brain | `claude-opus-4-8` | Adaptive thinking, streaming, `effort: high`. NDJSON emitted as text (not structured outputs) so lines can be parsed *as they stream*. System prompt prompt-cached. |
| SVG-diff agent | `claude-opus-4-8` | Streaming partial-JSON edits, cached system prompt. Runs on every draw; if latency feels heavy, drop to `claude-haiku-4-5`. Start on Opus and measure. |
| Voice | OpenAI Realtime | See §6. |

NDJSON-over-text is intentional: structured outputs would return a single JSON object, which cannot
be parsed line-by-line to start speech/drawing early. All Claude calls stream.

---

## 6. Voice Layer — Realtime as the voice device (V1)

The original leaned on LiveKit for the hard real-time audio (mic capture, VAD, echo cancellation,
**barge-in**). Dropping LiveKit means something must give that back. **Decision: OpenAI Realtime is
the voice device; Claude stays the brain.**

- One WebRTC connection handles mic capture, audio playback, server VAD, **barge-in**, and input
  transcription.
- The browser mints an **ephemeral Realtime key** via `GET /api/realtime-token` (the standing API
  key never reaches the client).
- **Output:** Claude's `speak` text is fed to Realtime to be voiced (assistant-item injection).
- **Input:** user speech is transcribed by Realtime; the transcript is forwarded to `/api/teach`
  as the next user turn. Server VAD interrupts playback for barge-in.
- **Fallback seam:** if driving Realtime to speak exact text proves awkward, swap output to OpenAI
  streaming TTS while keeping Realtime for input + VAD.

The voice layer sits behind a small interface (`speak(text)`, `onUserUtterance(cb)`, `interrupt()`)
so the loop code doesn't depend on Realtime specifics.

---

## 7. UI

- **Canvas** — the SVG drawing surface, center stage.
- **Progress strip** — a minimal "step 2 of 4" indicator. No sidebar, no clickable roadmap.
- **Text input** — the learner can type a question at any time (in addition to voice).
- Home page: a single topic input → starts a session.

---

## 8. Explicitly Out of Scope

Auth / anonymous IDs, projects & lessons, Postgres and all persistence, session resume, S3 image
uploads, non-English TTS, the inactivity pause controller, end-of-node follow-up options, roadmap
versioning + regeneration, LiveKit rooms and the data-channel topic protocol.

## 9. Components & Boundaries

| Unit | Responsibility | Depends on |
|------|----------------|-----------|
| `useTeachingSession` (hook) | Owns session state (steps, index, transcript), drives the loop | teach client, draw handler, voice layer |
| NDJSON parser | Incrementally parse streamed action lines; tolerate partial lines | — (pure, unit-tested) |
| `applySvgLineEdit` | Apply one `{start_line,end_line,content}` edit to an SVG string | — (pure, unit-tested) |
| draw handler | Call `/api/draw-svg`, apply edits with animation delay, return final SVG | SVG applier, canvas |
| voice layer | `speak(text)`, `onUserUtterance(cb)`, `interrupt()` over Realtime | Realtime, `/api/realtime-token` |
| `/api/plan` | Topic → 3–4 teaching steps | Claude |
| `/api/teach` | One turn of NDJSON actions | Claude |
| `/api/draw-svg` | Stream SVG line edits | Claude |
| `/api/realtime-token` | Mint ephemeral Realtime key | OpenAI |

---

## 10. Testing

TDD on the pure, high-value seams:
- **NDJSON incremental parser** — partial-line handling, malformed-line tolerance, multi-line turns.
- **`applySvgLineEdit`** — line-range replacement, insertions, out-of-range handling.
- **Step-plan schema** — validation of `/api/plan` output shape.

Voice + streaming integration is validated by running the app end-to-end.

---

## 11. Environment Variables

```
ANTHROPIC_API_KEY   # teacher + SVG-diff agent
OPENAI_API_KEY      # Realtime voice (ephemeral keys minted server-side)
```

No database URL, no LiveKit keys, no third-party STT/TTS keys, no AWS/S3.

---

## 12. Build Order (for the plan phase)

1. Scaffold the single Next.js app + env wiring.
2. Pure units first (TDD): NDJSON parser, `applySvgLineEdit`, plan schema.
3. `/api/plan` + `/api/teach` + `/api/draw-svg` (Claude, streaming).
4. Canvas + draw handler (animated SVG edits) — validate drawing with a hardcoded instruction.
5. Voice layer behind its interface (`/api/realtime-token` + Realtime client) — validate speaking.
6. `useTeachingSession` loop wiring speak + draw + advance.
7. Barge-in + text-question interruption.
8. Minimal UI (home input, canvas, progress strip).
